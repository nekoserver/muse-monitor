# muse-monitor の Tailscale 再ログイン仕様

対象は、本体 Worker の監視機能がサービスバインディングで参照する `muse-monitor` の MonitorGateway。管理画面の認証と Tailscale ノードの参加は独立して判定する。

| 要件 | 判定条件と期待する動作 |
|---|---|
| 保存済みノードの復帰 | 保存状態が有効なら同じノードで復帰する。状態が `Running` ならログインし直さない。保存状態で `NeedsLogin` になったときだけログインを試みる。 |
| 承認リンクが発行されない固着 | `NeedsLogin` のまま60秒が経過し承認リンクも無かった試行を、保存済み起動記録から検出する。次の起動・再確認では鍵を付けずに同じノードの対話ログインを要求する。この条件で保存状態を破棄しない。 |
| 公開ヘルスと再試行 | 公開 `/health` は起動済みインスタンスの固着に対して、対話ログインへの切り替えを1インスタンスにつき1回だけ駆動できる。同時アクセスで再試行を重複させない。 |
| 承認リンクの取得と更新 | 承認リンクは認証済みのステータス応答だけに含める。起動記録と公開ヘルスでは発行の有無を返す。画面はログイン中に5秒ごとに状態を読み直す。対話ログインの期限が切れたら、認証済みの再確認で新しいリンクを再発行できる。 |
| 対話ログイン | Tailscale ノードが未ログインで承認リンクが発行されたら、認証済みの監視画面にリンクを表示する。利用者はリンクを開き、`muse-vm` と同じ tailnet への参加を承認できる Tailscale アカウントを選ぶ。承認後、監視画面は次回の状態取得でログイン済みの表示に切り替える。 |
| データ取得欄の有効化 | ブラウザのキー認証が有効で、公開ヘルスでノードが `Running` と確認できた場合に、データ取得欄のグレーアウトを解除し、解除に続いて全項目を1回取得する。両条件がそろっている間は各項目の再取得と全件取得を操作できる。定期確認だけでは全件取得を繰り返さない。ノード再確認と承認リンクはデータ取得欄の外で使える。 |
| ブラウザ認証と受信側認証 | ブラウザのキーまたは Cookie が無効なときは HTTP 401 を返し、画面を未認証に切り替える。受信側が Worker の送った鍵を拒否したときは HTTP 502、`receiver_unauthorized`、`upstreamStatus: 401` を返す。再取得欄に受信側エラーを表示し、ブラウザの認証表示と操作可否を維持する。 |
| 復旧判定 | 承認リンクの表示は承認待ちとして扱う。公開ヘルスで `node.node = Running`、`node.loginPending = false`、`node.receiverResolved = true` がそろったときに復旧と判定する。 |

## 検証

- `test/do.test.ts` では、60秒の固着記録を入れた新規インスタンスと、稼働中のインスタンスを検査する。保存状態の維持、対話ログインへの切り替え、公開応答の秘匿、期限切れ後のリンク再発行、承認後の受信側への到達を確認する。
- `test/index.test.ts` では、未認証の再確認が拒否されることと、画面が遅れて届くリンクを取り直すことを検査する。
### データ取得の境界

| 経路 | 認証と状態の要件 |
|---|---|
| 監視画面 | ブラウザ認証とノードの状態がそろうまで取得要求を送らない。どちらかを失ったらデータ欄をロックし、表示済みの監視データと旧状態で開始した応答を破棄する。 |
| 通常 API | 正しい Bearer 鍵または期限内の認証 Cookie を検証してから MonitorGateway に転送する。処理中に Cookie の期限が来た場合も、監視データを返さず HTTP 401 にする。 |
| 本体 Worker の API | 用途別の有効な HMAC 署名を1回だけ受け付ける。この経路でも MonitorGateway のノード状態判定を適用する。 |
| ライブ WebSocket | ブラウザの Cookie では同一 origin からのみ接続できる。接続時に検証した期限をサーバー側で保持し、手動更新と定期配信の双方で確認する。期限切れの接続は閉じる。 |
| MonitorGateway | ノードが `Running` になるまで監視項目を取りに行かない。受信処理中に切断された場合は、再接続していてもその応答を破棄する。ライブ配信でも切断をまたいだ監視データを配信しない。 |

検証では、画面を介さない API 呼び出し、処理途中の Cookie 期限切れ、別 origin からの WebSocket、接続後の期限切れ、受信中のノード切断と再接続を網羅する。

### 実環境での受け入れ条件

1. Tailscale ノードの未ログイン時に、認証済みの監視画面で有効な承認リンクが表示される。期限切れの場合は「ノード再確認」で再発行できる。
2. リンク先で対象 tailnet のアカウントを選び、参加を承認する。監視画面がログイン済みに切り替わることを確認する。
3. [公開ヘルス](https://muse-monitor.nekoflare.workers.dev/health) で対象リビジョンと復旧判定の3項目を確認する。本体 Worker 側の連携を変更した場合は、認証済みの本体 Worker 経由でも監視項目を1件読み取る。
